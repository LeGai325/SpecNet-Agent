# Quality-Contract Broker 新范式实验（2026-08-16）

## 结论先行

本轮没有继续调 `boost` 或 `trigger`，而是把 optional 分支改写成可审计的质量契约：每条契约包含预测效用、字节成本、选择概率和不确定性折扣；控制器先求满足质量目标的最小字节组合，数学上不可行时再协商降级目标。

验证集准入审计得到三条可靠结论：

1. 不确定性折扣为 0 时，新规划器在 V1/V2 共 716 个工作流上与 V4 逐分支 100% 一致，因此没有伪造新的点估计资源收益；
2. 强折扣下，固定 0.95 契约使 V1/V2 的准入字节相对 V4 分别增加 41.78%/59.77%，其中 17.13%/39.72% 的工作流在 retain limit 下数学上不可行；
3. 只对不可行工作流协商到 validation 选出的 0.94 候选后，相对“固定 0.95 + 全开回退”收回 17.20%/26.12% 的准入字节，本轮 validation 样本拒绝率为 0。

这些 bytes 是准入需求，不是实际 served bytes、能耗或生产成本。分层契约仍未进入事件模拟器，不能声称已经改善 P99 或真实资源。

## 新范式是什么

```text
请求 0.95 质量契约
        |
        v
计算 retain limit 下的稳健质量上界
        |
        +-- 可行 --> 选择满足 0.95 的最小字节组合
        |
        +-- 不可行 --> 尝试 0.94 降级契约
                         |
                         +-- 可行 --> 最小字节组合 + 显式记录降级
                         |
                         +-- 不可行 --> 拒绝/转人工/延后，不盲目全开
```

运行时的下一层不是再加固定优先级，而是让每个 workflow 维护 byte-debt；质量、字节、拥塞和公平性各有影子价格。资源超预算会提高 byte price，欠服务会提高 fairness credit，每次动作都有可核对的账。

## 实现修正

- `select_minimum_byte_portfolio`：小分支数下精确枚举，以 bytes、分支数、稳定 ID 依次决胜；
- `select_quality_tier`：从高到低授予第一个可行契约，所有 tier 不可行才拒绝；
- `VirtualByteDebtLedger`：修正“债务注销后追加预算”的守恒关系；
- `ShadowPrices`：修正公平债务符号，欠服务越多应提高而不是降低优先级；
- 不可行回退的效用只计算 judge 最多可保留的分支，避免把全部已准入分支误算成质量收益。

## 对三项证明的影响

- 证明一不变：C/S/P 的消融证据仍来自冻结的因子化实验；本轮没有把契约规划器结果混入显著性结论。
- 证明二得到新的机制解释：固定规则跨 profile 不稳定，不只是阈值选错，还因为同一个硬质量契约在不同模板组成下可能从可行变成不可行。自适应控制应当调整契约和资源价格，而不只是调优先级。
- 证明三得到更强的审计对象：现在可以打印“请求 tier、授予 tier、分支组合、预测下界、字节成本、债务变化”，比只打印 Q 表更接近可验证解释。

## 必须保留的批评

1. `expected_utility` 已包含 selection probability，当前强折扣又按不确定性做一次 haircut；它只是敏感性压力测试，不是统计置信下界。
2. V1 validation 缺少模板多样性，不能用它证明跨模板泛化；V2 的 `rag_qa` 集中失败需要独立复核。
3. 0.94 是从 validation 可行前沿得到的降级候选。冻结后才能去独立 split 确认，不能根据确认失败再回调它。
4. 准入最优不等于调度最优。分支可能因排队未完成，事件模拟器仍需测实际 quality、served bytes、P95/P99 和 miss。
5. 目前没有真实答案质量标签，无法诚实地做 conformal calibration；应先采集预测效用与真实质量增益的配对样本。

## 下一阶段验收门

1. 在派生 simulator 中加入分层契约，但保留 V5 为调度 baseline；
2. 分别报告 primary/degraded/rejected 三组质量，禁止用总体平均掩盖降级；
3. 相对 V5/V4 检查 mean/P95/P99 served bytes、P99 latency、miss、waste 和每个压力组上界；
4. 每次分支服务同时记入 workflow/global debt，仿真末尾必须逐账户守恒；
5. 只在 V1/V2 validation 做机制筛选，冻结后再用独立 split 一次确认；
6. 若 0.94 仍依赖全开或造成尾延迟回归，应保留负结果，转向拒绝/延后，而不是继续降低质量直到结果好看。
